# AMAUN — Methodology

Written for: readers of the eventual paper, and reviewers checking that the implementation
matches the claims. Notation follows `idea.md` §2.2.

---

## 1. Setting

A frozen small/medium language model `f_θ` receives a sequence of tasks. Only LoRA parameters
are ever trained:

```
θ_{k+1} = θ_k = θ_0                       backbone frozen for the entire lifecycle
W_l^adapt = W_l^0 + ΔW_l                  adapted layer
ΔW_l = B_l A_l,   B_l ∈ R^{d_out×r}, A_l ∈ R^{r×d_in},   r ≪ min(d_in, d_out)
```

Because `θ` never changes, **every** adapter — including one trained at task 50 — is fitted from
the same `θ_0`. Sequential *arrival* therefore does not imply sequential *training*, which is
why "six independently trained adapters" and "tasks arriving in sequence" are compatible rather
than contradictory requirements.

## 2. The decision problem

The core move is to separate two questions that a similarity ranking conflates:

- *How related are two adapters?* → feature extraction (7 heterogeneous families)
- *Is integrating them actually beneficial?* → a learned utility predictor

Adapter management becomes a decision problem under predicted utility, not a similarity ranking.
Concretely, for each arriving task `t` and each `A_i ∈ R_c`:

```
z_i = [z_sem ; z_par ; z_grad ; z_perf ; z_cl ; z_hist ; z_res]    (54 features)
û_i = g_ω(z_i) = [ŝ_post, F̂, ĉ, M̂em, Ĉomm, L̂]ᵀ
U_i = wᵀ ψ(û_i)
i*  = argmax_i U_i
```

`ψ` orients each head so larger is better and `w` is non-negative, making `U` **monotone** in
each oriented outcome. Without that constraint gradient descent could learn a negative weight on
the forgetting head, and the network would prefer candidates that forget *more* while reporting
high utility — a failure invisible in the scalar.

The outcome is then

```
REUSE  if U_i* ≥ τ_reuse and the support-set pre-screen passes
FUSE   if U_i* ≥ τ_u
CREATE otherwise
```

`τ` is *selected*, never chosen: from a disjoint decision-development stream, by maximising
balanced accuracy at separating integrations that turned out beneficial from those that did not.
The selection procedure is recorded in every decision record.

## 3. Supervision that does not exist a priori

The utility targets are not available in advance. They are generated by **performing** candidate
integrations and measuring the result:

```
y_i = [s_post, F_post, C_post, Mem_post, Comm_post, L_post]ᵀ
L_U = Σ_i ‖ g_ω(z_i) − y_i ‖²
```

This is the dominant cost of the project: `O(T·n)` fusion runs for the bootstrap and `O(n²)` for
compression supervision. A truncated-fusion **proxy** bounds it, and a configurable fraction of
pairs is also run to convergence so the proxy's bias is *measured* rather than assumed small.
Everything here reads TRAIN/VALIDATION/SUPPORT; no TEST handle exists in the module.

## 4. Fusion

For `m` contributing deltas per layer:

```
ΔW_merge_l = Σ_k α_{l,k} ΔW_{l,k},    α_l = softmax(a_l),   Σ_k α_{l,k} = 1
a_l⁽⁰⁾ = 0  ⟹  α_{l,k}⁽⁰⁾ = 1/m       (= 0.5 for m = 2, as idea.md §6.1 requires)
```

At `m = 2`, `softmax([a,0])₁ = sigmoid(a)`, so this is *exactly* `idea.md`'s pairwise form, not
an approximation of it.

Two implementation points matter:

- **Fusion is at the `ΔW` level.** Averaging `A` and `B` independently is a different (wrong)
  operation, since `mean(B)@mean(A) ≠ mean(B@A)`.
- **The dense delta is never materialised.** `x@(Σ_k α_k s_k B_k A_k)ᵀ = Σ_k α_k s_k ((x A_kᵀ) B_kᵀ)`
  is exact and costs `O(r)` rather than `O(d_in·d_out)` memory. One 7B MLP projection would
  otherwise need ~68M floats per fused layer.

The fused adapter's storage form is an explicit choice (`dense_delta`, `refactorize_svd`,
`keep_components`), and the SVD option records its per-layer reconstruction error, so the
constant-adapter-size claim is measured rather than asserted.

## 5. Knowledge distillation

```
q_old   = softmax(s_old / T)      teacher = the PRE-MERGE old adapter
q_merge = softmax(s_merge / T)    student = the fused adapter
L_KD    = T² · mean_n KL(q_old ‖ q_merge)      on response positions of D_rep
L_total = L_new + λ · L_KD
```

The teacher is the old adapter, not the frozen backbone: the preservation target is the
behaviour fusion would otherwise overwrite, and the backbone has no such behaviour. Teacher
logits are captured **before** fusion is constructed; capturing them afterwards would distil the
student against a partially-merged model, a plausible-looking bug that would quietly weaken the
KD ablation. The step order is asserted, not documented.

`φ_merge` and `a` are optimised jointly in one backward pass with separate learning rates.

## 6. Repository lifecycle

```
REUSE  : R'_c = R_c                          (nothing grows)
FUSE   : R'_c = (R_c \ {A_i*}) ∪ {A_merge}   (count flat, tasks-served grows)
CREATE : R'_c = R_c ∪ {A_temp}               (count grows)
compress while Mem(R_c) ≥ R_max:  (i*,j*) = argmax_{i≠j} U_merge(A_i, A_j)
```

Compression reuses the **same** utility mechanism as selection, so the framework has one
decision principle across creation, merging and compression. An age/usage heuristic exists only
as baseline B6.

Adapters are archived, never deleted, so the growth trajectory stays auditable — a growth-control
claim whose counter-evidence has been removed is unfalsifiable.

## 7. Federated layer

```
C_k = { c : client c reports compatible adapter state k }
A_global_k = Σ_{c∈C_k} (n_c / Σ_j n_j) · A_c,k
```

Compatibility is gated explicitly (identical backbone fingerprint, target modules, rank, and a
declared grouping key) rather than assumed; blindly averaging unrelated adapters would defeat
the mechanism the paper is about. Aggregation happens at the delta level, weights are verified to
sum to 1, and payload sizes are measured from real serialised bytes. The backbone is never in a
payload, and a check for backbone-shaped tensors enforces it.

Communication savings are reported against a **like-for-like** counterfactual
(`n_transmissions × |θ| × b`); comparing cumulative LoRA traffic against a single full-model
payload would overstate the saving by a factor of `n_transmissions`.

## 8. Metrics

Per task, one `primary_score ∈ [0,1]` (ROUGE-L, token-F1, …) is the scalar used by every
decision and every continual metric. "Accuracy" is not used: five of the six tasks are
open-ended generation, where it is undefined.

```
AvgPerf_T  = (1/T) Σ_j S[T][j]
Forgetting = (1/(T−1)) Σ_{j<T} max(0, max_{i<T} S[i][j] − S[T][j])
BWT        = (1/(T−1)) Σ_{j<T} (S[T][j] − S[j][j])
FWT        = (1/(T−1)) Σ_{j>1} (S[j−1][j] − b_j)
```

Forgetting is clipped (per `idea.md` §4.5) while BWT is signed, so they measure different things;
both are reported, because reporting only one would hide either backward transfer or forgetting.
FWT requires the frozen backbone's adapter-free zero-shot score `b_j`, measured once — without it
FWT is reported as undefined rather than silently taking a baseline of zero.

Efficiency is reported jointly: adapter count, **tasks-served-per-adapter**, stored parameters,
storage bytes, and performance. Adapter count alone can make fusion look free, so the reporting
helper refuses to build a row that omits the others.

## 9. Novelty framing

None of the ingredients is claimed as novel: LoRA, knowledge distillation, FedAvg and weighted
fusion are all established. The contribution is their integration into one mechanism:

1. a multi-criteria adapter **utility** formulation — expected-utility decision, not
   single-metric similarity;
2. a **merge-or-create lifecycle** decision that can keep a new adapter when nothing meets the
   bar;
3. **layer-wise learnable** fusion coefficients, one per transformer layer;
4. **KD-guided joint optimisation** with the old adapter as behavioural teacher;
5. **unified compression** reusing the same utility principle rather than an ad-hoc heuristic;
6. a **federated adapter lifecycle** with LoRA-only communication over a permanently frozen
   backbone.

The closest prior work is adapter-fusion and model-merging literature plus federated
parameter-efficient tuning. **This repository does not assert priority over any specific paper**:
verifying that claim requires a literature review that has not been done here, and
`docs/decision_register.md` D-007 records that three named baselines cannot even be implemented
without their references. Any novelty statement in a paper must be supported by that review.
